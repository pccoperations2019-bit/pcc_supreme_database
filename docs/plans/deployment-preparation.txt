Fresh database backup preparation
New-ProductionDatabaseBackup.ps1 is a Windows PowerShell 5.1 administrator
procedure, not a GitHub job or deployment-account capability. It copies the
reviewed PHP helper into a unique protected backup directory before execution.
SYSTEM/Administrators alone receive access to C:\ProgramData\SUPREME-Backups.
Existing directories with unexpected permissions are rejected, not repaired.
The fixed live configuration hash, database target, server version and InnoDB
metadata are rechecked. mysqldump 8.0.40 uses single-transaction/quick with no
table locks and exports triggers/routines/events as well as tables and views.
No application restart, migration, import or Git remote change is performed.

Coordinate no schema/DDL changes during the export; pass
-NoSchemaChangesConfirmed only when that condition is satisfied. This online
export adds read/I/O load. It is not a synchronized application/upload snapshot.
Credentials exist briefly in an administrator-only option file, never in the
command line. A child-only MYSQL_TEST_LOGIN_FILE excludes unrelated login-path
settings. Temporary credentials are removed on normal/failure completion;
after a forced process kill or server crash, an administrator must check for
and remove any leftover mysql-client.cnf inside the exact backup directory.
SQL and diagnostic logs stay on the server and must not be posted or committed.
The report records time, byte size, SHA256 and export exit status, explicitly
restoreVerified=false and activationAllowed=false. Failed partial dumps remain
protected for diagnosis and are not treated as recovery backups. A successful
export still needs an isolated restore test, a current application/upload
backup and a protected off-server copy before recovery can be considered ready.
